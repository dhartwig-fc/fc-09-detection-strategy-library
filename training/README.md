# TM Tuning — training programme

Ten weeks, run alongside the NEXUS Tuning Studio build (fc-10, Stage560). Each
week teaches one tuning concept, the same week builds the studio feature that
performs it, and the week ends with a written decision.

Plan of record: fc-10 `docs/superpowers/specs/2026-09-24-tm-tuning-studio-and-training-plan.md`

## The weekly rhythm

| When | Time | What | Where |
|---|---|---|---|
| Monday | 1 h | Read the concept and the model-governance material | `weekNN_*/README.md` |
| Wednesday | 1 h | Work the notebook against the TM-SIM population | `weekNN_*/*.ipynb` |
| Friday | 1–2 h | Build session: the studio feature, with a mutation-verified guard | fc-10 |
| Weekend | 30 min | One-page recommendation | `weekNN_*/weekend_note.md` → from week 3, the fc-10 Tuning Decision Log |

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
export FC10_REPOSITORY=~/nexus-code/.worktrees/tuning-studio
.venv/bin/jupyter lab training/
```

The notebooks read the **same** population the studio measures, generated by
fc-10's `tm_sim` — nothing is copied here. Every rate is against PLANTED TRUTH,
never SAR outcomes.

`pytest` in this repository checks that fc-10's hand-written metrics agree
with scikit-learn on that population. The notebooks teach; the parity test
makes the teaching a check on the build.
